# 会话控制

输入框始终使用发送箭头图标，任务运行时另显示停止方形图标。发送按钮与 Enter 遵循“任务运行时的发送方式”设置，默认排队发送；Ctrl/Cmd+Enter 临时使用另一种方式，Shift+Enter 换行，输入法确认不发送。设置沿用 DSH 的 `ui-conversation.busyEnter` 持久化偏好。

排队消息持久化到服务端会话索引，当前任务正常完成后按顺序发送，不依赖浏览器保持打开。每条消息提供“立即追加”和移除图标；停止、失败或运行时重启后保留待发送消息，由用户选择发送。提交失败保留消息并显示错误。

立即追加时，Codex 通过 `turn/steer` 携带当前 `expectedTurnId` 追加输入；Harness 使用 `agent.steer`；Kimi ACP 在当前 prompt 取消并结束后，向同一个原生 session 提交补充指令。空闲会话使用普通发送。过期的 steer 返回冲突错误并保留输入草稿。

“分支 Fork”复制当前可见历史；用户消息下的“从此处分支”保留到该消息所在回复的边界。“编辑并重发”只保留被编辑消息之前的历史，再发送替换内容。若原任务还在运行，先等待它停止。分支使用新的会话标识，原会话可通过“返回原会话”访问；此操作不回滚文件。

“侧聊 BTW”或 `/btw 问题` 打开独立侧栏会话。新侧聊使用创建时的主会话快照，后续对话不写回主会话，也不取消主任务。侧聊不出现在普通会话列表中，可从主会话重新打开；“新侧聊”取得新的上下文快照。桌面端可拖动分隔线调整侧聊宽度，宽度随浏览器刷新保留；窄区域继续上下排列。

删除侧聊会清除会话、消息和浏览器中的打开状态。删除期间仍在完成的发送请求或模型回调只能结算已有额度，不再写回会话索引和消息，因此刷新或重启后不会恢复已经删除的侧聊。

## 历史与持久化

- 会话索引记录 `parentSessionId`、`branchKind`、`anchorMessageId` 和 `contextMode`。
- Codex 在静止会话中使用原生 `thread/fork` 和 `lastTurnId` 保留历史。
- Kimi、Harness、旧消息缺少原生轮次标识、运行中的分支，以及同一原生轮次内的细粒度编辑，使用 `transcript` 模式：仅将选定的用户和助手消息作为历史背景传入第一次新请求。这种模式不复制隐藏的工具调用记录或模型推理状态。
- 未发送的历史背景存为 `pendingContext`，首次成功提交后清除。未发送的原生侧聊延迟到第一次发送时创建，避免恢复尚未持久化的空原生会话。
- 已经通过文字历史恢复的分支继续按文字历史分支，避免把祖先会话的原生轮次 ID 用到新的原生会话。
- 同一轮内不同 Codex 助手消息按原生 item ID 保存，避免中间回复覆盖最终回复。

## 接口

会话接口以 `/api/runtime/v1/sessions/:id` 为前缀，沿用现有鉴权和员工隔离。

| 请求              | 输入                                                                           | 结果                            |
| ----------------- | ------------------------------------------------------------------------------ | ------------------------------- |
| `POST /turns`     | `content`，可选 `messageId`、`displayContent`                                  | 普通发送，202                   |
| `GET/POST /queue` | 读取队列；提交 `content/messageId`；或 `messageId/action`（steer/send/remove） | 持久化排队及逐条操作            |
| `POST /steer`     | 同上                                                                           | 追加指令，202；无运行任务时 409 |
| `POST /fork`      | 可选 `messageId`；编辑时增加 `replacementContent`                              | 新分支会话，201                 |
| `POST /side-chat` | 可选 `messageId`                                                               | 新侧聊会话，201                 |

编辑必须指定用户消息；空白替换内容被拒绝。并行输入请求受到会话级提交保护；编辑停止超时不会启动修订任务。

## 验证

删除会话会释放该会话的额度预留。若额度申请仍在进行，等待申请结束后再结算，保留日志以供异常重启恢复；已删除会话的迟到发送和模型事件不能重建会话或消息。

`harness-bundle/src/conversation-controls.test.ts` 覆盖原生分支边界、编辑历史、运行中编辑先停止、Kimi 历史恢复、侧聊重启恢复、删除后的迟到发送/模型事件和 steer 状态检查。原生引擎单元测试覆盖 Codex 的轮次匹配和 Kimi 取消收尾顺序；客户端组件测试覆盖编辑草稿、失败恢复、steer 和 `/btw` 路由。

`node scripts/smoke-dsh-conversation-controls.mjs` 使用现有 smoke 环境变量，登录后通过浏览器分别验证 Codex、Kimi 的真实上下文、编辑重发、分支、BTW 刷新和 steer。可通过 `WORKAGENT_SMOKE_EVIDENCE_DIR` 保存截图。

`WORKAGENT_SMOKE_ENGINES=kimi` 可限定引擎。`node scripts/smoke-dsh-conversation-layout.mjs` 使用受控会话数据，检查桌面、文件面板打开和手机宽度下两个聊天区域及输入框不重叠。`node scripts/smoke-dsh-side-chat-polish.mjs` 还检查拖动、键盘调宽、边界、刷新持久化和窄屏隐藏分隔线。窄区域中主聊天和侧聊上下排列，可滚动切换。

`node scripts/smoke-dsh-queue.mjs` 验证发送／停止图标、中文设置与刷新持久化，逐引擎通过真实消息验证排队、逐条立即追加与自动续发，并保存桌面及手机宽度截图。
