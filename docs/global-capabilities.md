# 员工全局 Skill / MCP 同步

Codex 按原来的方式安装，WorkAgent3 在员工运行时启动后及每 5 秒检查一次。设置中的“技能”和“MCP 服务”显示发现的能力；“检查新安装”可以立即同步。无需另走上传或导入流程。

## 范围

- 读取当前员工实际使用的 `dataRoot/native/codex/config.toml`、该 Codex home 下的 `skills`，以及配置中启用的插件。插件版本选择遵循 Codex 的缓存规则：`local` 优先，否则选当前最高版本。
- 读取员工数据目录内的 `.agents/skills`。脚本建立的共享引用使用 `wa3-<登记ID>` 命名，重复扫描会按实际目标去重。
- 不递归扫描工作区，不把项目 `.agents/skills`、`.codex/config.toml` 或项目插件提升为全局。不同员工拥有独立的目录、登记和凭据。
- 不扫描管理员的 Codex 安装，不将其配置复制给员工。当前扫描范围不包含任意自选的外部 Codex home。

## 技能

原始安装保留原位。目录引用同时提供 SKILL.md、scripts、references 等同目录资源，不复制整套插件。停用仅从全局自动注入与未绑定会话中排除，已绑定助手仍可用，平台建立的公共引用保留；删除登记不会删除原安装，也不会在下次扫描时重新创建登记。

原文件升级后引用仍指向原资源；插件版本切换会更新引用目标。相同名称的不同来源不会覆盖已有技能，而会在设置中显示冲突。插件声明依赖 Codex 托管应用时，其技能只分配给 Codex。

Codex 使用额外技能目录和会话级技能开关。Kimi Code 0.29 的 ACP 没有采用父级 `--skills-dir` 参数，但支持 `extra_skill_dirs`；因此同步器保留 Kimi 的其他配置及原有附加目录，只维护自己登记的技能目录。项目发现仍由原生引擎处理。DSH 通过现有技能提供器读取同一份引用。

## MCP

连接配置进入现有 MCP 目录，环境变量和请求头内容进入现有凭据库。同步状态文件只记录来源、ID、状态和时间，不保存这些凭据。

兼容且启用的全局服务默认加入新会话，原有助手显式绑定仍保留。Codex 使用原生服务名称覆盖同一个配置项，避免登记ID形成重复工具；停用或删除后仍保留必要的原生抑制记录。项目同名 MCP 配置优先，不被全局同步覆盖。

HTTP 服务仍要求 HTTPS，回环地址可使用 HTTP。缺失命令、环境变量或不支持的配置会显示待处理状态。托管应用连接、OAuth 或引擎专用选项不能仅凭目录复制变成通用 MCP。连接是否健康以现有“测试连接”结果为准，未测试不标记健康。

来源和设置发生冲突时保留设置，不静默覆盖。原安装消失时保留登记并标为不可用；源文件恢复后可再次同步。模型认证刷新采用配置合并，保留已经安装的 MCP 和用户配置；格式损坏的原生配置保留原文件并返回错误。

## 会话生效

平台在新会话中记录当时解析出的能力集合。已有会话的“重新加载能力”只允许在空闲时执行，保留会话ID、原生历史、消息和模型选择；执行中的会话返回忙碌，不打断任务。

接口沿用员工运行时鉴权：

- `GET /v1/capability-sync/status`
- `POST /v1/capability-sync/run`
- `POST /v1/sessions/{id}/capabilities/reload`

## AI管家

在首页助手列表选择“AI管家”。它使用普通会话，历史、模型选择和权限机制与其他助手一致。

管家绑定随版本发布的 `workagent-butler` MCP，提供 `butler_help`、`butler_overview`、`butler_read`、`butler_configure` 四个工具。查询帮助、诊断和配置直接调用现有助手、技能、MCP 和消息渠道接口。可以检查新安装、启停能力、测试 MCP、创建或修改助手、配置渠道账号的助手/模型/项目/权限、重连和启停接收。扫码绑定和第三方授权由用户在消息渠道设置中完成，管家不替代本人授权。普通已授权操作先读取、修改后读回；不发送未获用户授权的测试消息。

管家默认使用 Codex，可复制助手后调整引擎；保留管家说明的副本也绑定管理工具。原生引擎继续隔离平台凭据。员工私有 `dsh-home/workagent/runtime-gateway.json` 保存当次运行的回环地址和单独的管家配置凭据；该文件不能公开或放入项目。服务端限制此凭据的路由和方法，不能调用内部接口、管理员接口或发送会话消息。MCP 服务自动读取它并脱敏响应，不把密钥写入提示词或命令行。原始安装文件及其他员工数据不通过管家接口开放。

帮助说明随版本打包，运行问题结合实时状态回答。模型授权和额度仍由平台管理，不因管家存在而绕过权限。

## 验证

`internal/userhost/capability_sync_test.go` 覆盖重复同步、停用、删除、凭据不进入状态文件、员工/项目边界和插件版本。技能目录引用、原生配置保留、默认能力集合及空闲重载有对应测试。

`scripts/smoke-global-capabilities.mjs` 使用隔离目录和虚构认证配置，调用实际 Codex/Kimi 程序及 DSH 技能提供器，不调用付费模型、不访问真实外部 MCP。它检查共享资源、原生技能发现、Kimi 停用过滤、MCP 初始化，以及 Codex 的实际工具调用和资源读取。

同一脚本通过实际 Codex 调用管家 MCP，验证状态读取、测试渠道配置写入和读回、密钥脱敏及内部接口拒绝。配置写入仅发生在隔离的测试接口，不改真实渠道或发送外部消息。

`harness-bundle/src/butler.test.ts` 验证助手开关持久化、配置接口写入及读回、脱敏和路由边界；`internal/userhost/butler_test.go` 验证服务端访问范围。浏览器验证入口和现有设置，`scripts/smoke-puxin-butler.mjs` 用真实管家会话执行只读状态检查，保留验收任务。
