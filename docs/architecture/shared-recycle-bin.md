# 协作项目回收站

本功能延续协作项目直写同一共享文件夹的方案，不创建个人副本。协作文件管理中的删除，以及接入同一受控接口的删除操作，会将文件或整个目录移入中央回收站。

## 使用规则

- 在协作文件管理顶部，点击“加号”右侧的回收站图标。页面复用文件管理容器、工具栏及列表样式，只显示当前项目的删除项；成员不能查看或操作其他项目的条目。
- 文件最多保留 **7 天**。所有成员、所有协作项目共用 **60 GiB**（60 × 1024³ 字节），超过时按删除时间从早到晚清理；同一时间使用持久化入池顺序。因此空间不足可能令文件提前过期。
- 可以恢复条目，也可以永久删除。恢复回到记录的原相对路径，必要时重建父目录。已有同名文件或目录时返回 `409 file_exists`，请先在项目文件中重命名或移走同名项，再恢复；系统不覆盖现有内容。
- 协作项目所有权转移后，旧回收项仍属于相同项目，恢复到当前所有者的项目目录。恢复仍受现有共享存储硬配额约束；搬回失败时保留回收内容。

## 存储、权限与接口

Portal 在每次列表、恢复、永久删除及回收操作时校验当前项目成员资格和项目状态。浏览器不能指定可信的 owner SID 或绝对路径。Portal 将授权后的项目标识交给 SYSTEM 身份的 Employee Manager，后者通过受服务凭证保护的 `POST /v1/shared-trash/{projectID}` 统一执行操作。

中央目录为 `<DataRootBase>/.workagent-shared-trash/<projectID>/<entryID>/`，包含 `metadata.json` 与 `payload`，位于个人及每位所有者的共享配额根之外。列表仅返回当前项目条目，以及全池和本项目的合计占用。中央目录不向员工授予读取权限；NTFS 移动会保留原 ACL，因此每个移入载荷的全部子项都重新设置为 SYSTEM/管理员私有。恢复复制当前项目根的所有者与 DACL，使退组及成员变化同时生效。整个链路拒绝路径逃逸和重解析点。

回收前持久化 `recycling` 日志；恢复和永久删除分别持久化 `restoring`、`purging` 阶段。文件已完成移动及 ACL 投射后，索引收尾或保留策略清理失败会记录日志并由维护任务重试，接口仍报告已提交操作成功，避免运行时漏记已删除文件身份。永久删除先移除经过校验的 `payload`，再清理日志，不递归删除整个条目容器中的未知附加文件。删除未完成的剩余字节继续计入全池占用。

Employee Manager 使用同一个互斥锁串行管理全池，在启动和每分钟维护时恢复未完成日志、导入旧回收项并执行过期和容量清理；不依赖浏览器打开或员工运行时在线。临时元数据写入放在条目父目录，避免中断写入阻塞有效日志；未知临时文件及其他附加文件不因名称猜测而删除。

## 旧机制兼容与覆盖边界

只导入协作项目下已有的 `.workagent-trash`，不扫描个人项目、技能或会话存档。历史名称只有时间、随机标识和原文件名，原父目录已丢失；导入后标记为历史条目，以文件名恢复到项目根，不猜测原目录。能识别的旧删除时间保存在 `legacyDeletedAt`，保留期从首次导入重新计算 7 天；不识别的正常文件名原样保留。无法安全识别的内容留存并记录。

本回收站不是操作系统文件拦截器。任意 shell、原生 CLI、第三方程序直接执行的 `rm`、`Remove-Item` 或文件系统删除，若绕过受控回收接口，**不在保证覆盖范围内**；文件监听不能找回已经被直接删除的字节。共享目录已有的变更感知与写保护保持原逻辑，未改写项目 `AGENTS.md` 或全局 preset。
