# 前端字号与输入控件规范

2026-09-12 用户补充要求。本文是后续前端整改和验收必须遵守的规范；不表示现有全部页面已经满足，也不表示已完成真机验证。

## 手机输入字号下限

所有手机页面采用以下固定下限，单位为 CSS px。档位控制其他界面文字的大小，但不能把可编辑区域缩到对应下限以下。

| 字体档位 | 设置存储值 | 手机输入字号下限 |
| --- | --- | --- |
| 紧凑 | 13 | 16px |
| 标准 | 14 | 16px |
| 大号 | 16 | 18px |
| 特大 | 18 | 20px |

这里的下限是全部样式应用后的最终计算字号，包括默认、聚焦、输入、自动填充和报错状态。输入控件有更大字号的明确用途时允许更大。下限只定义一次，普通输入组件、聊天编辑器、Portal 登录/管理端及上游适配共同遵守。

WebKit 当前的 iOS 聚焦缩放实现使用 16 作为标准字号，并由标准字号与输入字号的比值计算目标比例。因此本项目把 16px 作为紧凑与标准的输入保底；18/20px 为大号和特大保留清晰的档位差异。依据：[WebKit 的 iOS 聚焦缩放实现](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/ios/WKWebViewIOS.mm#L1547)。这不是对所有系统辅助功能和用户页面缩放设置的无条件保证。

## 覆盖范围

- 登录、改密、个人任务、协作、频道、项目文件、市场、助手、定时任务、系统设置和管理端的所有可编辑输入。
- 文本、搜索、密码、邮箱、电话、数字等输入；textarea、select；contenteditable 聊天/消息编辑区；侧栏搜索、行内重命名、弹窗、浮层和挂载到独立节点的控件。
- 不把 checkbox、radio、开关、文件选择触发按钮等无可编辑文字的控件误当成文本输入。
- 横屏、竖屏都必须生效。不能只用 <=600px 或 <=760px 宽度判断手机输入的下限，也不能依赖祖先类名恰好包含 workagent。
- 不按 iPhone 型号降低安全下限。Pro Max 的紧凑档与其他机型的标准档属于重点验收组合，其他手机和档位也遵守同一规则。
- 页面采用正确的设备宽度和初始缩放。禁止通过 CSS transform/zoom 缩小输入控件，或等到聚焦后才放大字号来规避该要求；保留用户手动缩放能力。
- 输入文字和占位文字遵守同一下限；较小的说明、标签、计数可位于输入框外，使用说明文字字号。

## 必测组合与完成条件

| 真机 | 重点字体档位 | 目标 |
| --- | --- | --- |
| iPhone 17 Pro Max | 紧凑 | 点击任何输入框均不因输入字号过小而自动放大页面 |
| iPhone 17 | 标准 | 同上 |
| iPhone 17 Pro | 标准 | 同上 |

1. 本地自动检查四档字体、横竖屏布局、浅深主题，以及全部已盘点页面和弹窗的最终输入字号；同时确认内容和发送/保存按钮不被挤出或遮挡。
2. 自动检查覆盖上游设置和频道控件、动态打开的弹窗及可编辑区域。不能仅测几个聊天框就声明所有页面通过。
3. 真机使用 Safari 和项目实际使用的主屏幕入口，默认页面缩放下，记录聚焦前、键盘出现后和退出输入后的 viewport scale。键盘引起的视口高度变化或为露出光标而滚动是正常行为；不应把它们当作缩放失败。
4. 验收保留系统/iOS 版本、浏览器入口、页面缩放设置、字体档位及失败输入框位置。桌面 Chromium/WebKit 的尺寸模拟只能证明字号和布局，不能替代真实 iPhone 键盘聚焦验收。

当前状态：公共控件与两个页面入口已实现四档输入下限，规则覆盖窄屏及带触摸输入的横屏设备。Chromium/WebKit 的字号和聚焦计算、登录/管理端成品检查已通过；真实 iPhone 键盘聚焦验收尚未进行，不能用桌面模拟代替。
