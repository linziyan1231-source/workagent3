# 管理员提供的 ACP 引擎

员工从「设置 → 助手 → 管理员提供的 ACP 引擎」填写个人连接信息，再创建使用该引擎的助手。助手可用于普通会话、协作项目内个人任务、团队成员和定时任务。协作项目的统一共享助手仍沿用其原有引擎范围。

管理员在「管理空间 → ACP 引擎」启用、停用或选择已批准的目录版本。网页不能提交可执行命令、下载地址或任意启动参数。启用新版本只影响新建会话；已有会话保存原目录版本。停用目录会阻止已有会话的新一轮请求，正在等待的原生审批和取消操作仍可处理。

## 发布目录

Portal 的 `--acp-catalog` 指向当前不可变软件发布内的 JSON 数组；`--acp-state` 是发布目录之外的可写启停状态文件。默认没有额外引擎。软件包由管理员随正常不可变发布流程提供，员工只读执行。目录可以同时包含同一个 `id` 的多个不同 `revision`。仍需恢复的旧会话版本必须在新发布目录中保留对应包；缺少已冻结版本会明确拒绝恢复，不自动换引擎。

首次提供引擎时，管理员在候选发布中准备完整的公开软件包：ACP 可执行入口、固定版本 Node/Python 解释器（若入口需要）、入口脚本及全部依赖。`command` 必须是包内可直接启动的程序；不使用员工启动时在线安装的 `npx` / `pip` 命令。所有会执行的代码都随公共软件发布，个人 API Key 不放入包或清单。

候选包本地验证完成后，在同一发布中加入目录文件，并给 Portal 包装服务增加 `--acp-catalog <目录文件绝对路径>`。启停状态默认保存在 Portal 数据库旁的 `acp-catalog.json`，也可用 `--acp-state` 显式指定持久化位置。按正常整套软件发布流程激活后，管理员即可在网页启用该版本；员工填写个人字段、建立 ACP 助手后即可使用。没有批准的软件包时可发布空数组 `[]`，网页显示空目录，之后通过下一次不可变发布增添首个引擎。

```json
[
  {
    "id": "approved-agent",
    "label": "团队提供的助手引擎",
    "packageRef": "packages/approved-agent-v1",
    "revision": "v1",
    "command": "node.exe",
    "args": ["agent.mjs"],
    "credentialFields": [
      {
        "id": "api-key",
        "label": "API Key",
        "environment": "AGENT_API_KEY",
        "required": true
      }
    ],
    "billingModelId": "codex-native",
    "enabled": false,
    "permissionModes": { "read_only": "plan", "workspace_write": "auto" }
  }
]
```

`packageRef` 相对目录文件所在目录，`command` 相对软件包。可执行文件必须真实位于已批准包内；路径逃逸和指向包外的链接会被拒绝。启动参数固定在发布清单内。进程从可执行文件所在目录启动，所以上例 `agent.mjs` 与 `node.exe` 同目录；引擎通过 ACP `session/new` 的 `cwd` 获得任务工作目录。入口程序不能向公共软件目录写入缓存或日志，应使用个人环境中的 `ACP_HOME`、临时目录和任务工作目录。

`revision` 标识不可变的目录声明。运行时解析的绝对软件路径不会改变冻结身份，因此整个 WorkAgent 发布目录迁移不会自行替换引擎配置。目录声明中的凭据环境变量不能覆盖 PATH、用户目录、WorkAgent 内部身份和解释器注入选项等执行环境。

## 连接信息、权限与能力

个人字段保存于所属员工的 Credential Broker。公开目录只返回字段名、是否已保存和是否可连接；不返回环境变量值。UserHost 创建独立的 `acp-gateway.json` 私有作用域，普通浏览器代理令牌和 AI 管家令牌不能读取此内部接口。每次准入和取凭据都会重新检查管理员启停状态。

已启动的引擎进程继续使用启动时取得的连接信息。更换或清除字段后，新信息在下次引擎启动时生效；员工可在系统设置中重启个人运行环境，界面会提示正在执行的工作会中断。

标准 ACP 通信与 Kimi 共用一处实现。恢复、模型、命令等能力从引擎协商或通知获得；不承诺未提供的 OAuth、模式或压缩命令。没有管理员权限映射时使用引擎原生审批。若员工明确选择权限模式，必须在目录映射和引擎实际模式中同时存在。

命令列表可在首轮消息之前更新，并在会话内动态替换。命令补全保留原始斜杠输入。审批保留引擎给出的选项标识和说明；Codex 的会话与规则授权保持区别。ACP 的 `allow_always` / `reject_always` 表示由引擎记住选择，其持续范围依引擎说明，不将其一律解释为仅当前会话。

## 配额

`billingModelId` 必须引用员工已有授权、且管理员已配置额度的模型预算。会话中的模型选择不会改变这个固定计费项。ACP 请求保守预留用量；成功发出后，即使失败、中断或重启，也按保存的估算量结算。尚未发出的请求释放预留。当前估算沿用任务准入规则：输入 UTF-8 字节数除以 4 向上取整，再加 1024 单位。

这属于估算记账，不等同于外部服务商的精确 Token 或美元账单。ACP 预留明确记录引擎类型，不等待无关网关记录，不会把网关没有记录解释为免费。用量页的对应模型预算会包含 ACP 的估算消费。真正需要精确计费的目录必须另行提供可信用量通道。

## 本地验证

覆盖目录版本持久化、路径限制、私密作用域、凭据脱敏、停用后的准入与取消、早到命令通知、原生审批选项、冻结计费、取消窗口和重启结算。协议测试使用本地假 ACP 进程，不调用外部付费服务。
