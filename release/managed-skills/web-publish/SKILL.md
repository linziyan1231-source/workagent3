# 网页发布

把当前项目（工作区）里的网页发布成在线链接。所有操作使用内置 MCP 工具 `workagent-app-publish`（`app_publish` / `app_publish_list`）；不要自己启动服务器或猜测端口。

## 发布前准备

1. 把要公开的网页和它的依赖放进项目里的一个独立目录，确认入口文件存在（通常是 `index.html`）。发布会保存入口所在目录的快照，网页只使用自己的数据空间。
2. **确定工作区**：入口文件在哪个工作区，发布时就必须用那个工作区的 `workspaceId`。
   - 如果文件放在当前项目根目录（`default` 工作区），用 `workspaceId: "default"`。
   - 如果文件放在其他工作区（例如 `web test`），必须传入对应工作区 ID，**不能默认用 `default`**。
   - 不确定时，先列出工作区并检查入口文件实际位置，再发布。
3. 发布前必须向用户确认两件事，不要替用户默认决定：
   - **有效时间**：默认 5 天，可按用户要求调整；到期后网页自动不可访问。
   - **访问范围**：
     - `authenticated`：仅 WorkAgent 登录用户可访问；
     - `token`：任何人凭带密钥的完整链接访问（链接内含访问令牌，不需要登录）；
     - `password`：任何人凭 8 位访问密码访问（不需要登录）。
4. 如果是更新已发布的网页，先用 `app_publish_list` 找到它的 `appId`，发布时带上 `appId`，这样会保留原链接和访问设置。

## 发布

调用 `app_publish`：

- `name`（必填）：网页名称，用户能看懂的名字。
- `access`（必填）：上面确认的访问范围。
- `entry`：入口文件相对工作区根目录的路径，默认 `index.html`；入口所在目录会被整体发布。
- `workspaceId`：入口文件所在工作区的 ID。**不要留空，不要默认用 `default`，除非你确认文件确实在 default 工作区。**
- `validDays`：有效天数，默认 5。
- `appId`：更新已有网页时传入。

成功后把结果原样转告用户：

- `shareUrl`：分享链接（token 模式已包含访问令牌）。
- `accessCode`：仅 password 模式返回，8 位访问密码，需要告诉用户。
- `expiresAt`：到期时间。

链接和密码以工具返回为准，不要自行编造。发布失败时如实报告错误，不要声称已发布。

## 端口与故障排查

- token/password 模式的分享链接使用平台分配的**专用端口**（如 `http://<服务器>:<端口>/t/<令牌>/`）。端口范围由管理员在 **管理空间 → 应用发布** 中配置，并必须与服务器云防火墙开放的端口段一致；链接打不开时先提醒用户/管理员核对这个范围，不要反复重试发布。
- 每个账号同时发布的网页有端口数上限（默认 3 个，管理员可调整）。发布返回 `application_employee_ports_exceeded` 时，引导用户在 **设置 → 网页发布** 删除不再需要的网页后重试；返回 `application_ports_exceeded` 时提示联系管理员扩大端口范围。
- 其他失败会把服务端错误码直接返回，原样转达给用户即可。

## 查看与管理

- 用 `app_publish_list` 查看当前已发布的网页（名称、链接、访问范围、有效期、启停状态）。
- 用户也可以在 **设置 → 网页发布** 里查看、停用/启用或删除网页；停用和删除由用户自己在设置里操作，不要代替执行。
